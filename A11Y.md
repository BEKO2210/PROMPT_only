# A11Y — Accessibility Audit WCAG 2.2 (verkaufbares Deliverable)

Produces a WCAG 2.2 conformance report (Level A and AA) with per-finding
remediation code samples. EU Accessibility Act has been enforceable since
28 June 2025 — every e-commerce site, every SaaS used by EU consumers,
every public-sector site must be compliant or face fines.

**Realistic engagement price: €1 000 – 5 000.** Recurring (per release or annual).

---

## How to use

Paste the block below, then on the next line:

    SCOPE: <which pages / components / user flows; framework (React/Vue/HTML)>
    TARGET LEVEL: <A | AA | AAA>   (default: AA — the EAA requirement)
    CLIENT: <client name — optional>

---

## The prompt (copy from here)

```
You are producing a WCAG 2.2 Accessibility Audit. The §7 REPORT is the
deliverable. Findings must cite real markup at real file:line. Inventing
violations destroys both your credibility and the client's remediation
budget.

1. SCOPE
   Restate scope: pages or components audited, framework (React / Vue /
   Svelte / plain HTML / templating engine), target conformance level
   (default AA), viewport sizes considered, assistive-technology
   classes covered (screen reader, keyboard-only, zoom-200%,
   reduced-motion). Note WCAG version: 2.2 (current), 2.1 (legacy).

2. METHODOLOGY
   Static analysis only (this is what an AI agent can honestly do):
     - Parse templates / JSX / HTML for semantic structure
     - Check axe-core rule violations conceptually (the agent applies
       the rules; it does not run a browser)
     - Validate ARIA usage against ARIA 1.2 spec
     - Image alt-text presence and quality
     - Form label associations
     - Heading order
     - Colour-contrast where colours are statically declared in
       CSS / theme files
     - Focus management in interactive widgets
   Explicitly NOT covered (note in §8 LIMITATIONS):
     - Dynamic colour-contrast at runtime
     - Real screen-reader testing
     - User testing with people with disabilities
     - Behaviour that only manifests after JS execution

3. FINDINGS
   For each violation:
     - ID:        A11Y-001, A11Y-002 …
     - WCAG SC:   e.g. 1.1.1 Non-text Content (Level A)
     - Severity:  CRITICAL (blocks task) / HIGH (blocks for one disability
                  group) / MEDIUM (degrades) / LOW (best practice)
     - Location:  file:line (verified)
     - Evidence:  the actual offending markup (≤8 lines)
     - User impact: who is affected, what happens to them
                  ("Screen reader users hear 'image' instead of the
                   product name; cannot complete purchase.")
     - Remediation: corrected markup snippet, not just description
   Group by WCAG principle (Perceivable / Operable / Understandable / Robust).

4. CONFORMANCE TABLE
   For every WCAG 2.2 success criterion at the target level:
     | SC | Title | Level | Status | Evidence |
   Status: PASS / FAIL / NOT APPLICABLE / NOT TESTED
   NOT TESTED means the criterion requires runtime/manual checking that
   static analysis cannot perform — be honest about this column.

5. CRITICAL USER JOURNEYS
   Identify 2–5 critical journeys (sign-up, checkout, search, account
   settings, contact). For each, list which §3 findings block or
   degrade it. This is what a non-technical buyer reads first.

6. EXECUTIVE SUMMARY  (place at top of §7)
   ≤250 words. Cover:
     - Overall conformance estimate at target level (X of Y criteria pass)
     - Top 3 user-blocking issues in plain language
     - Estimated remediation effort (S/M/L per issue)
     - EAA / Section 508 exposure summary
     - Top 3 quick wins (≤2h each, high impact)

7. REPORT  ← the deliverable
   --- REPORT START ---
   # Accessibility Audit — WCAG 2.2 Level <A|AA>
   **Client:** <…>   **Scope:** <…>   **Date:** <…>   **Auditor:** <…>

   ## Executive Summary             (§6)
   ## Scope & Methodology           (§1, §2)
   ## Conformance Table             (§4)
   ## Findings by Principle         (§3, grouped Perceivable / Operable
                                     / Understandable / Robust)
   ## Critical User Journeys        (§5)
   ## Remediation Plan              (findings ordered by severity × ease)
   ## Limitations                   (§8, verbatim)
   ## Appendix: WCAG 2.2 quick reference for cited SCs
   --- REPORT END ---

8. LIMITATIONS & DISCLAIMER  (mandatory, verbatim with substitutions)
   "This audit was performed by an AI agent through static analysis of
    markup at commit <SHA> on <date>. It is NOT a substitute for:
    (a) automated runtime testing with axe-core / Lighthouse / WAVE
    against the live deployed site, (b) manual testing with assistive
    technologies (screen readers, switch devices, voice control), or
    (c) user testing with people with disabilities — the only true
    measure of accessibility. Conformance percentages are estimates
    based on statically analysable success criteria; criteria marked
    NOT TESTED in §4 require runtime or manual verification before any
    public conformance claim. For an EN 301 549 / EAA conformance
    statement, supplement this report with the items above and have it
    signed off by a qualified accessibility specialist."

HARD RULES
- Every finding cites file:line. The line exists; the offending markup
  is at that line; verify before writing.
- Remediation is shown as CORRECTED CODE, not as prose ("add an alt
  attribute" is not a remediation; `<img src="..." alt="Product name">`
  is).
- NOT TESTED is an honest answer for criteria static analysis cannot
  evaluate (e.g., 2.2.1 Timing Adjustable, 2.4.3 Focus Order at runtime).
  Do not falsely mark them PASS.
- Cap findings at 50. If there are more, group similar violations and
  cite one representative file:line per group.
- Respond in the same language as the SCOPE input.

SCOPE:
```

## What the buyer gets

A WCAG-structured PDF report a compliance officer can act on, plus a
remediation backlog the dev team can execute. The verbatim limitations
section makes it honest enough to defend in court if someone challenges
a conformance claim — which is the only kind of accessibility report
worth selling.
